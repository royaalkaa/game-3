# Выкладка на сервер

Игра запускается двумя контейнерами. `app` работает с игрой, `caddy` принимает HTTPS и сам получает сертификат Let's Encrypt.

## 1. Сервер

- Любой VPS с Ubuntu 24.04: 2 vCPU, 2 ГБ памяти, публичный IP. За раунд на 200 игроков приходит около 40 МБ фото, канала 100 Мбит хватает.
- **Сервер должен стоять вне России.** OpenAI не принимает запросы с российских IP, и все фото уйдут ведущему. Подойдёт, например, Европа.
- В фаерволе провайдера открыть порты 80 и 443 (TCP), а для HTTP/3 ещё 443 по UDP.

## 2. Адрес

Свой домен: A-запись на IP сервера, например `game.example.ru`.

Без домена: `<ip-через-дефисы>.sslip.io`. Для IP `203.0.113.7` это `203-0-113-7.sslip.io`. Сервис sslip.io сам указывает такое имя на этот IP, и Let's Encrypt выдаёт на него сертификат.

## 3. Установка

```bash
curl -fsSL https://get.docker.com | sh
git clone https://github.com/royaalkaa/game-3.git
cd game-3
cp .env.example .env
nano .env
```

В `.env` заполнить:

| Переменная | Значение |
| --- | --- |
| `OPENAI_API_KEY` | ключ OpenAI |
| `PH_VISION_MODE` | `openai` (или `fake` для репетиции без ключа) |
| `PH_HOST_TOKEN` | длинный пароль ведущего, от 8 символов |
| `PH_DOMAIN` | домен из шага 2 |

`PH_PUBLIC_URL` не нужен: compose собирает его из `PH_DOMAIN`.

```bash
docker compose up -d --build
```

## 4. Проверка

```bash
curl https://<домен>/healthz
docker compose logs -f
```

Первый запуск может занять минуту, пока Caddy получает сертификат. Затем открыть `https://<домен>/songs`, войти паролем ведущего и загрузить песни. Экран для проектора: `https://<домен>/host`.

## Обновление

```bash
git pull
docker compose up -d --build
```

**Не обновлять и не перезапускать во время игры.** Игроки и фото хранятся в памяти, после перезапуска игра начинается заново. Песни и музыка лежат в томе `app-data` и переживают перезапуск и пересборку.

## Резервная копия песен

```bash
docker compose cp app:/app/data ./data-backup
```
